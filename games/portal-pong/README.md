# 04. Пинг-понг с порталом — Направление отскока

Мяч всегда отскакивает горизонтально. Пусть игрок управляет углом точкой удара о ракетку.

## Один блок реализации

Замените тело **[PaddlePhysics.reflectedVerticalSpeed](src/main/java/edu/course/games/portalpong/domain/PaddlePhysics.java)**. Это единственный `TODO` игры. Остальные методы и подключение к окну готовы; дополнительных обязательных классов или расширений нет. Приватные помощники допустимы, если они делают этот блок понятнее.

## Поведение

Вернуть (ballY-(top+55)) 5: угол отскока зависит от места попадания.

ballY и top конечны, abs ≤ 10^6. Требуемая сложность: O(1).

Примеры: reflectedVerticalSpeed(155,100) → 0; reflectedVerticalSpeed(145,100) → -50; reflectedVerticalSpeed(165,100) → 50.

## На что обратить внимание

Сопоставьте центр ракетки и два симметричных смещения. Затем перенесите все координаты на 100.

## Как выполнить и проверить

1. Откройте метод и его вызов в `PortalPongGame`. Для операций, вызванных через готовый адаптер, проследите цепочку до окна.
2. До реализации выпишите результат для обычного случая и указанной границы. Затем замените демозаглушку своим кодом.
3. После лекции 3 объясните результат и состояние данных при успехе и отказе. После лекции 4 закрепите эти случаи Jupiter-тестами; тесты в `src/test/java` уже доступны.
4. Запустите проверку выбранной игры и повторите действие в окне.

```sh
./mvnw -pl :portal-pong -am verify
./mvnw -DskipTests package
java -jar app/target/java-games-app-1.0.0.jar 4
```

Все команды — из корня проекта. В PowerShell используйте `.\mvnw.cmd`. Пока блок не написан, приёмочные тесты падают, а окно запускается с неполной механикой. После изменения кода нужна пересборка.

## Готово, когда

- Описанное действие работает в окне, а тесты выбранного модуля проходят без изменения ожидаемых результатов и без включения preview в тестах.
- Проверены обычный случай и перечисленные границы; для отказа проверены тип исключения и сохранность данных, если это обещано контрактом.
