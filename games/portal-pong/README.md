# 04. Пинг-понг с порталом — Управляемый отскок

Удар в центр ракетки даёт горизонтальный полёт, удары выше и ниже меняют знак вертикальной скорости.

## Что вы исследуете

Центр top+55 отличается от расширенной области столкновения с учётом радиуса мяча.

Темы: Чистые функции, перенос координат, свойства. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Перед началом

Предыдущая работа: [03. Облачный прыгун](../cloud-jumper/README.md). Переносите её практику проверки, а не её код.

Работа 4/25. Ориентир 90–120 минут. Сигнатуры и примеры заданы. Самостоятельно выберите контрпримеры.

## Обязательная работа: Калибровка трёх точек

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Проверьте центр и симметричные смещения. Добавьте свойство: перенос ballY и top на одно число не меняет попадание и скорость. Укажите допустимый диапазон генерации.
4. Тесты различают неверный знак, центр и коэффициент 5. Симметрия сама по себе не исключает функцию, всегда возвращающую 0.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в PaddlePhysics.

### `boolean intersectsPaddle(double ballY,double top)`

- **WHAT / contract:** Мяч попадает, если его центр находится в [top-10,top+120].
- **Constraints:** ballY и top конечны, abs ≤ 10^6. Требуемая сложность: O(1).
- **Examples:** intersectsPaddle(90,100) → true; intersectsPaddle(220,100) → true; 89 и 221 → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `intersectsPaddle`, не совпадающий с examples.
- **Typical pitfalls:** Ширина интервала включает радиус мяча; top+110 — не верхняя граница контракта.

### `double reflectedVerticalSpeed(double ballY,double top)`

- **WHAT / contract:** Вернуть (ballY-(top+55)) 5: угол отскока зависит от места попадания.
- **Constraints:** ballY и top конечны, abs ≤ 10^6. Требуемая сложность: O(1).
- **Examples:** reflectedVerticalSpeed(155,100) → 0; reflectedVerticalSpeed(145,100) → -50; reflectedVerticalSpeed(165,100) → 50.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `reflectedVerticalSpeed`, не совпадающий с examples.
- **Typical pitfalls:** Вычитать надо центр ракетки top+55; знак определяет движение вверх/вниз.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 4.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :portal-pong -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
