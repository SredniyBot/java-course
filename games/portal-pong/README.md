# 04. Пинг-понг с порталом

Отразите мяч 12 раз.

## Learning outcomes
Симметрия и знаки скорости. Java: Math, отражение, диапазоны. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 01. Уровень 1/3, ориентир 45–60 минут без установки JDK.

## Milestones
1. Нарисуйте два граничных примера на бумаге.
2. Реализуйте первый метод по описанию; прогоните тесты.
3. Реализуйте остальные методы, добавьте тест на границу.
4. Проверьте обычный ход и перезапуск окна.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в PaddlePhysics.

### `boolean intersectsPaddle(double ballY,double top)`

- **WHAT / contract:** Мяч попадает, если его центр находится в [top-10,top+120].
- **Constraints:** ballY и top конечны, abs ≤ 10^6. Требуемая сложность: O(1).
- **Examples:** intersectsPaddle(90,100) → true; intersectsPaddle(220,100) → true; 89 и 221 → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `intersectsPaddle`, не совпадающий с examples.
- **Typical pitfalls:** Ширина интервала включает радиус мяча; top+110 — не верхняя граница контракта.

### `double reflectedVerticalSpeed(double ballY,double top)`

- **WHAT / contract:** Вернуть (ballY-(top+55)) 5: угол отскока зависит от места попадания.
- **Constraints:** ballY и top конечны, abs ≤ 10^6. Требуемая сложность: O(1).
- **Examples:** reflectedVerticalSpeed(155,100) → 0; reflectedVerticalSpeed(145,100) → -50; reflectedVerticalSpeed(165,100) → 50.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `reflectedVerticalSpeed`, не совпадающий с examples.
- **Typical pitfalls:** Вычитать надо центр ракетки top+55; знак определяет движение вверх/вниз.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :portal-pong -am test`. Windows: `.\mvnw.cmd -pl :portal-pong -am test`.
Проверки находятся в `src/test/java/edu/course/games/portalpong/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 4`.
В IDE запустите `edu.course.app.Launcher` с аргументом `4`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Optional extension / запрос на защите

Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

## AI policy / check questions
Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `intersectsPaddle` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: Ширина интервала включает радиус мяча; top+110 — не верхняя граница контракта.
4. Выполните небольшой change request без повторной генерации всего класса.
