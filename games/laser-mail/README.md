# 18. Лазерная почта

Доставьте луч из левого края в приёмник (7,7), поворачивая зеркала.

## Learning outcomes
Таблица переходов и границы. Java: Массивы направлений, циклы, отражение. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 12. Уровень 3/3, ориентир 75–100 минут без установки JDK.

## Milestones
1. Напишите короткую design note: типы данных, границы ответственности, альтернативы.
2. Зафиксируйте BeamRules как адаптер для готового UI; внутренние классы, value objects и API проектируйте сами.
3. Реализуйте контракт и защитите выбор мутабельности; добавьте свои независимые тесты.
4. Обязательная защита: реализуйте запрос на изменение ниже и объясните, какие тесты защищают старое поведение.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в BeamRules.

### `int reflectDirection(int direction,char mirror)`

- **WHAT / contract:** Направления: 0 вправо,1 вниз,2 влево,3 вверх. Для /: 0→3,1→2,2→1,3→0; для обратного слеша: 0→1,1→0,2→3,3→2. Иначе направление не менять.
- **Constraints:** direction ∈ {0,1,2,3}; mirror любой char. Требуемая сложность: O(1).
- **Examples:** reflectDirection(0,'/') → 3; reflectDirection(3,'\\') → 2; reflectDirection(2,'.') → 2.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `reflectDirection`, не совпадающий с examples.
- **Typical pitfalls:** Перепутать / и \ легко; два отражения одним зеркалом возвращают направление.

### `boolean isInsideGrid(int r,int c,int h,int w)`

- **WHAT / contract:** Проверить обе координаты: 0<=r<h и 0<=c<w.
- **Constraints:** h,w ≥0; r,c любые int. Требуемая сложность: O(1).
- **Examples:** isInsideGrid(0,0,1,1) → true; isInsideGrid(1,0,1,1) → false; isInsideGrid(0,0,0,1) → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isInsideGrid`, не совпадающий с examples.
- **Typical pitfalls:** Правая/нижняя границы исключены; отрицательные координаты недопустимы.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :laser-mail -am test`. Windows: `.\mvnw.cmd -pl :laser-mail -am test`.
Проверки находятся в `src/test/java/edu/course/games/lasermail/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 18`.
В IDE запустите `edu.course.app.Launcher` с аргументом `18`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Обязательный design milestone и защита
Заменить направления enum и обнаруживать цикл по состоянию (клетка,направление).
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `reflectDirection` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: Перепутать / и \ легко; два отражения одним зеркалом возвращают направление.
4. Выполните небольшой change request без повторной генерации всего класса.
