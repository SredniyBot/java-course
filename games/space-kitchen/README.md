# 20. Космическая кухня — Две порции одного ингредиента

Сравнение через Set принимает тарелку с одной порцией вместо двух.

## Что вы исследуете

Мультимножество сохраняет кратность; пустой токен не равен отсутствию заказа.

Темы: Map, мультимножество, parsing/validation. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в RecipeRules.

### `String[] parseIngredients(String line)`

- **WHAT / contract:** Разделить непустую строку по запятым с сохранением пустых полей; каждый фрагмент strip + lowercase ROOT. Пустая или blank строка даёт массив длины 0.
- **Constraints:** line не null; пустые поля сохраняются только для неblank строки. Требуемая сложность: O(n).
- **Examples:** parseIngredients(" A,,B, ") → ["a","","b",""]; parseIngredients("  ") → [].
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `parseIngredients`, не совпадающий с examples.
- **Typical pitfalls:** split без отрицательного limit удаляет хвостовые пустые поля; Locale.ROOT обязателен.

### `boolean hasSameIngredients(String[] a,String[] b)`

- **WHAT / contract:** Проверить одинаковый набор с учётом повторов, порядок не важен. Исходные массивы не менять. Можно сортировать копии.
- **Constraints:** a,b и их строки не null; сравнение точное и регистрозависимое. Требуемая сложность: O(n log n+m log m), O(n+m) памяти.
- **Examples:** hasSameIngredients(["a","b","a"],["b","a","a"]) → true; ["a","a"] против ["a"] → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `hasSameIngredients`, не совпадающий с examples.
- **Typical pitfalls:** Set теряет повторы; сортировать входные массивы запрещено.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 20.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :space-kitchen -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
