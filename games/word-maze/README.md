# 12. Буквенный лабиринт — Маршрут без телепортации

Последняя клетка строки и первая следующей имеют соседние номера, но не общую сторону. Букву нельзя использовать дважды.

## Что вы исследуете

Линейный индекс не сохраняет соседство; проверка шага отличается от проверки маршрута.

Темы: List/Set, координаты, история. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

Предыдущая работа: [11. Спасите воздушный шар](../balloon-rescue/README.md). Переносите её практику проверки, а не её код.

Работа 12/25. Ориентир 210–240 минут. Кроме базовых методов обязательна новая модель с тестами и подключением к UI. Не складывайте состояние в static.

## Обязательная работа: Редактор маршрута

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Создайте WordPath с append(index), undo(), snapshot(). Первый шаг в любой клетке; следующие по стороне без повторов. Неверный индекс/шаг возвращает false без изменений. undo пустого пути возвращает false. snapshot защищает внутренний путь. Подключите UI.
4. Проверьте переход через край строки, цикл, undo с повторным использованием клетки, изменение копии. Обоснуйте коллекции.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в WordPathRules.

### `boolean areSideNeighbors(int a,int b,int width)`

- **WHAT / contract:** Индексы одной сетки. Разрешено соседство только по стороне, без переноса между строками.
- **Constraints:** width>0, a,b ≥0, до 10^6; индексы одной сетки в построчной нумерации. Требуемая сложность: O(1).
- **Examples:** areSideNeighbors(2,3,3) → false; areSideNeighbors(1,4,3) → true; areSideNeighbors(1,1,3) → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `areSideNeighbors`, не совпадающий с examples.
- **Typical pitfalls:** Разность индексов 1 может пересекать границу строки; диагональ не сосед.

### `String readPath(char[][] board,int[] path,int length)`

- **WHAT / contract:** Собрать буквы первых length индексов path в строку. Ширина board[0].length.
- **Constraints:** board непустой прямоугольный, width>0; path не null; 0≤length≤path.length; первые length индексов внутри board. Требуемая сложность: O(length).
- **Examples:** readPath([[J,A],[V,A]],[0,1,2,3],4) → "JAVA"; length=0 → "".
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `readPath`, не совпадающий с examples.
- **Typical pitfalls:** Используется ширина, а не высота; элементы path после length не читать.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 12.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :word-maze -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
