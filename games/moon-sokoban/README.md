# 17. Склад лунного сыра — Ящик застрял, игрок не двинулся

Игрок толкает ящик в стену и уже сдвинулся на экране, хотя ящик остался.

## Что вы исследуете

Игрок и ящики составляют одну транзакцию; цели не исчезают после ухода ящика.

Темы: Составные инварианты, undo, атомарность. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

Работа 17/25. Ориентир 285–315 минут. До реализации согласуйте контракт нового API в DESIGN.md. Обязательны модель, интеграция, проверки отказов и разбор компромиссов.

## Обязательная работа: Полный ход склада

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Создайте WarehouseState с отдельным immutable слоем стен/целей. move(direction) возвращает BLOCKED/WALKED/PUSHED. BLOCKED ничего не меняет. Добавьте undo успешного хода; blocked не добавляется в историю. Подключите UI.
4. Проверьте толчок на/с цели, два ящика, границу, undo после blocked. Объясните владение слоями и стоимость снимка.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в WarehouseRules.

### `boolean tryPushBox(int[][] b,int r,int c,int dr,int dc)`

- **WHAT / contract:** Клетка (r,c) содержит ящик 2. Если следующая по направлению клетка внутри поля и равна 0, перенести ящик туда и вернуть true; иначе оставить поле и вернуть false.
- **Constraints:** b непустой прямоугольный; (r,c) внутри и содержит 2; |dr|+|dc|=1; строки разные. Требуемая сложность: O(1).
- **Examples:** tryPushBox([[2,0]],0,0,0,1) → true, поле [[0,2]]; для [[2,1]] → false и поле неизменно.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `tryPushBox`, не совпадающий с examples.
- **Typical pitfalls:** При заблокированном ходе нельзя сначала стереть исходный ящик; диагонали не входят в контракт.

### `boolean allGoalsOccupied(int[][] b,boolean[][] goals)`

- **WHAT / contract:** Каждая целевая клетка содержит ящик 2.
- **Constraints:** b/goals одинакового прямоугольного размера; строки не null. Требуемая сложность: O(h*w).
- **Examples:** b=[[2,0]], goals=[[true,false]] → true; goals=[[false,true]] → false; без целей → true.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `allGoalsOccupied`, не совпадающий с examples.
- **Typical pitfalls:** Вне целей могут быть лишние ящики; они не мешают выполнению этого условия.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 17.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :moon-sokoban -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
