# 17. Склад лунного сыра

Переместите два ящика на золотые площадки.

## Learning outcomes
Атомарность игрового хода. Java: Матрицы, условия, изменение состояния. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 06,08. Уровень 3/3, ориентир 90–120 минут без установки JDK.

## Milestones
1. Напишите короткую design note: типы данных, границы ответственности, альтернативы.
2. Зафиксируйте WarehouseRules как адаптер для готового UI; внутренние классы, value objects и API проектируйте сами.
3. Реализуйте контракт и защитите выбор мутабельности; добавьте свои независимые тесты.
4. Обязательная защита: реализуйте запрос на изменение ниже и объясните, какие тесты защищают старое поведение.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в WarehouseRules.

### `boolean tryPushBox(int[][] b,int r,int c,int dr,int dc)`

- **WHAT / contract:** Клетка (r,c) содержит ящик 2. Если следующая по направлению клетка внутри поля и равна 0, перенести ящик туда и вернуть true; иначе оставить поле и вернуть false.
- **Constraints:** b непустой прямоугольный; (r,c) внутри и содержит 2; |dr|+|dc|=1; строки разные. Требуемая сложность: O(1).
- **Examples:** tryPushBox([[2,0]],0,0,0,1) → true, поле [[0,2]]; для [[2,1]] → false и поле неизменно.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `tryPushBox`, не совпадающий с examples.
- **Typical pitfalls:** При заблокированном ходе нельзя сначала стереть исходный ящик; диагонали не входят в контракт.

### `boolean allGoalsOccupied(int[][] b,boolean[][] goals)`

- **WHAT / contract:** Каждая целевая клетка содержит ящик 2.
- **Constraints:** b/goals одинакового прямоугольного размера; строки не null. Требуемая сложность: O(h*w).
- **Examples:** b=[[2,0]], goals=[[true,false]] → true; goals=[[false,true]] → false; без целей → true.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `allGoalsOccupied`, не совпадающий с examples.
- **Typical pitfalls:** Вне целей могут быть лишние ящики; они не мешают выполнению этого условия.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :moon-sokoban -am test`. Windows: `.\mvnw.cmd -pl :moon-sokoban -am test`.
Проверки находятся в `src/test/java/edu/course/games/moonsokoban/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 17`.
В IDE запустите `edu.course.app.Launcher` с аргументом `17`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Обязательный design milestone и защита
Добавить undo для одного толкания, включая отказ хода.
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

## AI policy / check questions
Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `tryPushBox` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: При заблокированном ходе нельзя сначала стереть исходный ящик; диагонали не входят в контракт.
4. Выполните небольшой change request без повторной генерации всего класса.
