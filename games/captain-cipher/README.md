# 23. Шифр капитана

Расшифруйте пять приказов со сдвигом Цезаря.

## Learning outcomes
Модульная арифметика и переполнение. Java: char, остаток, StringBuilder. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 10,21. Уровень 3/3, ориентир 75–100 минут без установки JDK.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в CaesarCipher.

### `char shiftUppercase(char ch,int offset)`

- **WHAT / contract:** Для A…Z циклический сдвиг на offset (может быть отрицательным). Остальные символы не менять. Используйте Math.floorMod.
- **Constraints:** Любой char и любой int offset, включая MIN_VALUE и MAX_VALUE. Требуемая сложность: O(1).
- **Examples:** shiftUppercase('Z',1) → A; shiftUppercase('A',-1) → Z; shiftUppercase('!',7) → !; shiftUppercase('Z',MAX_VALUE) → W.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `shiftUppercase`, не совпадающий с examples.
- **Typical pitfalls:** Сначала нормализуйте offset: ch+offset может переполниться. Отрицательный % — не floorMod.

### `String encode(String text,int offset)`

- **WHAT / contract:** Применить shiftUppercase к каждому char, собрать строку.
- **Constraints:** text не null; любой offset; меняются только латинские A..Z. Требуемая сложность: O(n).
- **Examples:** encode("AZ-я",1) → "BA-я"; encode("",7) → "".
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `encode`, не совпадающий с examples.
- **Typical pitfalls:** lowercase и Unicode-символы сохраняются; нормализация регистра здесь запрещена.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :captain-cipher -am test`. Windows: `.\mvnw.cmd -pl :captain-cipher -am test`.
Проверки находятся в `src/test/java/edu/course/games/captaincipher/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 23`.
В IDE запустите `edu.course.app.Launcher` с аргументом `23`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Обязательный design milestone и защита
Ввести отдельный алфавит и заранее определить поведение дубликатов.
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

1. Объясните `shiftUppercase` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: Сначала нормализуйте offset: ch+offset может переполниться. Отрицательный % — не floorMod.
4. Выполните небольшой change request без повторной генерации всего класса.
