# 21. Unicode-сафари

Поймайте 10 карточек, удовлетворяющих заказу по числу кодовых точек или байтов.

## Learning outcomes
UTF-16, code countCodePoints, UTF-8. Java: char, code point, UTF-8, строки. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 10,11. Уровень 3/3, ориентир 90–120 минут без установки JDK.

## Milestones
1. Напишите короткую design note: типы данных, границы ответственности, альтернативы.
2. Зафиксируйте UnicodeText как адаптер для готового UI; внутренние классы, value objects и API проектируйте сами.
3. Реализуйте контракт и защитите выбор мутабельности; добавьте свои независимые тесты.
4. Обязательная защита: реализуйте запрос на изменение ниже и объясните, какие тесты защищают старое поведение.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в UnicodeText.

### `int countCodePoints(String text)`

- **WHAT / contract:** Посчитать Unicode-кодовые точки, не char. Используйте codePointCount на всей строке.
- **Constraints:** text не null; корректный UTF-16. Графемные кластеры специально не считаем. Требуемая сложность: O(n).
- **Examples:** countCodePoints("A😀") → 2; countCodePoints("é") → 2; countCodePoints("") → 0.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `countCodePoints`, не совпадающий с examples.
- **Typical pitfalls:** char, code point и видимый символ — три разных понятия.

### `int utf8Length(String text)`

- **WHAT / contract:** Число байтов при кодировании UTF-8; кодировку задать явно.
- **Constraints:** text не null; корректный UTF-16; кодировка UTF-8 без BOM. Требуемая сложность: O(n).
- **Examples:** utf8Length("A😀") → 5; utf8Length("Я") → 2; utf8Length("") → 0.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `utf8Length`, не совпадающий с examples.
- **Typical pitfalls:** Не использовать defaultCharset; размер в памяти UTF-16 — не размер UTF-8.

### `String prefixByCodePoints(String text,int n)`

- **WHAT / contract:** Вернуть первые n кодовых точек, не разрывая суррогатные пары. Если n больше количества, вернуть всю строку; n>=0.
- **Constraints:** text корректный UTF-16, не null; n≥0. Требуемая сложность: O(text.length).
- **Examples:** prefixByCodePoints("A😀B",2) → "A😀"; n=0 → ""; n=99 → вся строка.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `prefixByCodePoints`, не совпадающий с examples.
- **Typical pitfalls:** substring(0,n) индексирует char; составная графема может разделиться по контракту.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :unicode-safari -am test`. Windows: `.\mvnw.cmd -pl :unicode-safari -am test`.
Проверки находятся в `src/test/java/edu/course/games/unicodesafari/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 21`.
В IDE запустите `edu.course.app.Launcher` с аргументом `21`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Обязательный design milestone и защита
Отделить подсчёт графем от code countCodePoints; обосновать библиотеку или ограничение.
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

## AI policy / check questions
Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `countCodePoints` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: char, code point и видимый символ — три разных понятия.
4. Выполните небольшой change request без повторной генерации всего класса.
