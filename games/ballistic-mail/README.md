# 24. Баллистическая почта — Попадание между отсчётами

Посылка пролетает площадку между кадрами. Большой dt меняет исход при тех же начальных условиях.

## Что вы исследуете

Интеграция, пересечение поверхности и попадание имеют разные источники погрешности.

Темы: Численное моделирование, допуски, replay. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Обязательная работа: Симуляция с replay

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Вынесите ProjectileSimulation.step(dt) в domain с immutable snapshot. Задайте ускорение, единицы и схему интеграции. Для пересечения высоты цели интерполируйте x внутри шага; после посадки состояние терминально. Добавьте replay списка dt; подключите UI.
4. Проверьте 0/90 градусов, знак y, dt=0, пересечение между кадрами, два разбиения времени с обоснованным допуском. Сохраните вход дефекта.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в TrajectoryPhysics.

### `Velocity initialVelocity(double angle, double speed)`

- **WHAT / contract:** Вернуть Velocity(x, y): vx=cos(toRadians(angle))*speed, vy=-sin(toRadians(angle))*speed. Ось y экрана направлена вниз.
- **Constraints:** angle конечен abs≤36000 градусов; speed конечен ∈[0,10^6]. Требуемая сложность: O(1).
- **Examples:** initialVelocity(0,10) → Velocity(10,0); initialVelocity(90,10) → Velocity(≈0,-10). Допуск проверок 1e-8.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `initialVelocity`, не совпадающий с examples.
- **Typical pitfalls:** sin/cos принимают радианы; результат — value object, не массив с магическими индексами.

### `boolean isWithinTarget(double x,double target,double halfWidth)`

- **WHAT / contract:** Попадание при |x-target|<=halfWidth.
- **Constraints:** Конечные x,target abs≤10^6; halfWidth ∈[0,10^6]. Требуемая сложность: O(1).
- **Examples:** isWithinTarget(60,100,40) → true; isWithinTarget(140,100,40) → true; isWithinTarget(141,100,40) → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isWithinTarget`, не совпадающий с examples.
- **Typical pitfalls:** Обе границы включены; направление экранной y здесь не участвует.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 24.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :ballistic-mail -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
