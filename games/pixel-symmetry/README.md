# 13. Мастерская симметрии

Нарисуйте симметричный узор минимум из 20 цветных пикселей.

## Learning outcomes
Мутация, симметрия и инварианты. Java: int[][], границы, отражение. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 05. Уровень 2/3, ориентир 75–100 минут без установки JDK.

## Milestones
1. До реализации составьте таблицу граничных случаев и определите владельца массивов.
2. Реализуйте методы с соблюдением контрактов; самостоятельно выберите цикл и вспомогательные методы.
3. Добавьте тест отсутствия лишних изменений и один параметризованный тест.
4. Объясните сложность и продемонстрируйте игру.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в SymmetryRules.

### `void paintCell(int[][] image,int row,int col,int color)`

- **WHAT / contract:** Поставить цвет в клетку. Если индексы вне матрицы, ничего не менять.
- **Constraints:** image не null; строки не null, прямоугольность не обязательна; row,col любые int; color любой int. Требуемая сложность: O(1).
- **Examples:** paintCell([[1,2]],0,1,9) → [[1,9]]; row=-1 или col=2 → без изменений.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `paintCell`, не совпадающий с examples.
- **Typical pitfalls:** Выход за край здесь штатный no-op, а не исключение.

### `void mirrorLeftToRight(int[][] image)`

- **WHAT / contract:** Скопировать левую половину в правую, отражая относительно вертикальной оси. Нечётную центральную колонку сохранить.
- **Constraints:** Строки не null и разные объекты; допустимы разная длина и пустые строки. Требуемая сложность: O(числа элементов), O(1) доп. памяти.
- **Examples:** mirrorLeftToRight([[1,2,3,4,5]]) → [[1,2,3,2,1]].
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `mirrorLeftToRight`, не совпадающий с examples.
- **Typical pitfalls:** Копировать слева направо только половину; среднюю колонку не менять.

### `boolean isHorizontallySymmetric(int[][] image)`

- **WHAT / contract:** Проверить горизонтальное отражение в каждой строке. Не менять матрицу.
- **Constraints:** image и строки не null, в том числе пустые и разной длины. Требуемая сложность: O(числа элементов).
- **Examples:** isHorizontallySymmetric([[1,2,1],[]]) → true; isHorizontallySymmetric([[1,2]]) → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isHorizontallySymmetric`, не совпадающий с examples.
- **Typical pitfalls:** Проверка ничего не исправляет; пустая строка симметрична.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :pixel-symmetry -am test`. Windows: `.\mvnw.cmd -pl :pixel-symmetry -am test`.
Проверки находятся в `src/test/java/edu/course/games/pixelsymmetry/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 13`.
В IDE запустите `edu.course.app.Launcher` с аргументом `13`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

4. Выполните небольшой change request без повторной генерации всего класса.
