# 06. Змейка-курьер — Движущийся хвост

После хода координаты хвоста превращаются в копии головы: массив обновляли в неверном направлении.

## Что вы исследуете

Запись поверх ещё не прочитанных данных разрушает состояние; активная длина не равна вместимости.

Темы: Массивы, мутация, инвариант цикла. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Перед началом

Предыдущая работа: [05. Кирпичный сад](../brick-garden/README.md). Переносите её практику проверки, а не её код.

Работа 6/25. Ориентир 120–150 минут. Алгоритм и тестовый оракул выберите самостоятельно; объясните, почему они не повторяют друг друга.

## Обязательная работа: След одного хода

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Запишите старые и новые пары для тела длины 4. Проверьте неизменность неактивного хвоста и length=1. Добавьте три поворота с вручную выписанной траекторией.
4. Проверяйте xs и ys целиком. В occupancy включите клетку, которая есть только за пределами length.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в SnakeRules.

### `void advanceBody(int[] xs,int[] ys,int length,int nx,int ny)`

- **WHAT / contract:** Сдвинуть первые length элементов вправо и записать новую голову в [0]. Сдвиг справа налево; length>=1.
- **Constraints:** xs, ys не null и не один объект; 1 ≤ length ≤ min(xs.length,ys.length); любые int координаты. Требуемая сложность: O(length), O(1) доп. памяти.
- **Examples:** xs=[3,2,1,99], ys=[4,4,4,88], length=3, новая голова=(4,4) → xs=[4,3,2,99], ys без изменений.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `advanceBody`, не совпадающий с examples.
- **Typical pitfalls:** Сдвиг слева направо затирает тело. Хвост массивов с index≥length не менять.

### `boolean occupiesCell(int[] xs,int[] ys,int length,int x,int y)`

- **WHAT / contract:** Есть ли координата (x,y) среди первых length элементов. length может быть 0.
- **Constraints:** xs, ys не null; 0 ≤ length ≤ min длин. Требуемая сложность: O(length).
- **Examples:** occupiesCell([2,8],[3,9],1,8,9) → false; length=2 → true; length=0 → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `occupiesCell`, не совпадающий с examples.
- **Typical pitfalls:** Обе координаты должны совпасть в одной позиции, не в разных сегментах.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 6.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :courier-snake -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
