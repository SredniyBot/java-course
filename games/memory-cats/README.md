# 09. Котики-близнецы

Найдите восемь пар карточек.

## Learning outcomes
Равенство значений и идентичность. Java: String.equals, массивы, состояние. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 05. Уровень 2/3, ориентир 45–60 минут без установки JDK.

## Milestones
1. До реализации составьте таблицу граничных случаев и определите владельца массивов.
2. Реализуйте методы с соблюдением контрактов; самостоятельно выберите цикл и вспомогательные методы.
3. Добавьте тест отсутствия лишних изменений и один параметризованный тест.
4. Объясните сложность и продемонстрируйте игру.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в MatchingRules.

### `boolean isMatchingPair(String[] cards,int a,int b)`

- **WHAT / contract:** Индексы валидны. Пара — разные индексы с одинаковым текстом. Сравнивать содержимое, не ссылки.
- **Constraints:** cards и строки не null; a,b — действительные индексы. Регистр значим. Требуемая сложность: O(длины строки).
- **Examples:** isMatchingPair([new String("A"),new String("A")],0,1) → true; a=b → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isMatchingPair`, не совпадающий с examples.
- **Typical pitfalls:** == сравнивает ссылки; совпадение карточки с самой собой не пара.

### `int countRevealedCards(boolean[] found)`

- **WHAT / contract:** Посчитать найденные карточки.
- **Constraints:** found не null; длина может быть 0. Требуемая сложность: O(n).
- **Examples:** countRevealedCards([true,false,true]) → 2; countRevealedCards([]) → 0.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `countRevealedCards`, не совпадающий с examples.
- **Typical pitfalls:** Возвращать число карточек, а не число пар; found не менять.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :memory-cats -am test`. Windows: `.\mvnw.cmd -pl :memory-cats -am test`.
Проверки находятся в `src/test/java/edu/course/games/memorycats/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 9`.
В IDE запустите `edu.course.app.Launcher` с аргументом `9`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Optional extension / запрос на защите
Ввести record Card(id,label): какие поля определяют пару?
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

## AI policy / check questions
Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `isMatchingPair` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: == сравнивает ссылки; совпадение карточки с самой собой не пара.
4. Выполните небольшой change request без повторной генерации всего класса.
