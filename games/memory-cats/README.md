# 09. Котики-близнецы — Котики с одинаковыми паспортами

Карты загружены независимо: одинаковые подписи представлены разными объектами String. Двойной щелчок не образует пару.

## Что вы исследуете

Равенство значения и идентичность различаются; повтор и третий щелчок требуют явных переходов.

Темы: equals, enum/record, конечный автомат. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

Работа 9/25. Ориентир 165–195 минут. Кроме базовых методов обязательна новая модель с тестами и подключением к UI. Не складывайте состояние в static.

## Обязательная работа: Модель выбора пары

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. После базовых методов создайте PairSelection. pick(index) сообщает результат; один индекс нельзя выбрать дважды. После двух различных выборов pick отклоняется до resolve(), который сбрасывает выбор. Индексы 0..size-1; неверный индекс — IllegalArgumentException без изменения. Подключите UI.
4. Сдайте диаграмму empty→one→two→empty, тесты повторного/третьего выбора и resolve. Сравнение проверьте на new String с одинаковым текстом.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в MatchingRules.

### `boolean isMatchingPair(String[] cards,int a,int b)`

- **WHAT / contract:** Индексы валидны. Пара — разные индексы с одинаковым текстом. Сравнивать содержимое, не ссылки.
- **Constraints:** cards и строки не null; a,b — действительные индексы. Регистр значим. Требуемая сложность: O(длины строки).
- **Examples:** isMatchingPair([new String("A"),new String("A")],0,1) → true; a=b → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isMatchingPair`, не совпадающий с examples.
- **Typical pitfalls:** == сравнивает ссылки; совпадение карточки с самой собой не пара.

### `int countRevealedCards(boolean[] found)`

- **WHAT / contract:** Посчитать найденные карточки.
- **Constraints:** found не null; длина может быть 0. Требуемая сложность: O(n).
- **Examples:** countRevealedCards([true,false,true]) → 2; countRevealedCards([]) → 0.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `countRevealedCards`, не совпадающий с examples.
- **Typical pitfalls:** Возвращать число карточек, а не число пар; found не менять.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 9.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :memory-cats -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
