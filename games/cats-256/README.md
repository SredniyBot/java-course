# 16. Котики 256

Соберите плитку 256. Каждая плитка сливается не более одного раза за ход.

## Learning outcomes
Снимки, уплотнение и одноразовое слияние. Java: Сжатие массива, слияние, копии. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 06,07. Уровень 3/3, ориентир 120–180 минут без установки JDK.

## Milestones
1. Напишите короткую design note: типы данных, границы ответственности, альтернативы.
2. Зафиксируйте TileRules как адаптер для готового UI; внутренние классы, value objects и API проектируйте сами.
3. Реализуйте контракт и защитите выбор мутабельности; добавьте свои независимые тесты.
4. Обязательная защита: реализуйте запрос на изменение ниже и объясните, какие тесты защищают старое поведение.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в TileRules.

### `int[] mergeLeft(int[] row)`

- **WHAT / contract:** Вернуть новый ряд: убрать нули, слить соседние равные числа один раз слева направо, дополнить нулями. Оригинал не менять.
- **Constraints:** row не null; элементы 0 либо степени 2 ≤2^29; пустой ряд допустим. Требуемая сложность: O(n) времени/памяти.
- **Examples:** mergeLeft([2,2,2,2]) → [4,4,0,0]; mergeLeft([2,2,4,0]) → [4,4,0,0]; mergeLeft([2,0,2]) → [4,0,0].
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `mergeLeft`, не совпадающий с examples.
- **Typical pitfalls:** Полученный результат не сливается повторно в том же ходе; вход должен остаться прежним.

### `int[][] rotateClockwise(int[][] a)`

- **WHAT / contract:** Новая квадратная матрица, повёрнутая по часовой стрелке.
- **Constraints:** Квадратная матрица, строки не null; допустима матрица 0×0. Требуемая сложность: O(n²) времени/памяти.
- **Examples:** rotateClockwise([[1,2],[3,4]]) → [[3,1],[4,2]].
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `rotateClockwise`, не совпадающий с examples.
- **Typical pitfalls:** Это новый снимок; четыре поворота восстанавливают значения, но не ссылки.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :cats-256 -am test`. Windows: `.\mvnw.cmd -pl :cats-256 -am test`.
Проверки находятся в `src/test/java/edu/course/games/cats256/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 16`.
В IDE запустите `edu.course.app.Launcher` с аргументом `16`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Обязательный design milestone и защита
Вернуть MergeResult с новым рядом и начисленными очками; защитить массив от aliasing.
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

## AI policy / check questions
Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `mergeLeft` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: Полученный результат не сливается повторно в том же ходе; вход должен остаться прежним.
4. Выполните небольшой change request без повторной генерации всего класса.
