# 07. Тетрис: стройка на Луне — Два этажа за один ход

Две соседние заполненные строки исчезают одновременно, сохраняя порядок остальных этажей.

## Что вы исследуете

Сдвиг меняет индекс следующей строки; вращение прямоугольника меняет размеры, а нулевое обрамление не сталкивается со стеной.

Темы: Матрицы, копирование, стабильная компактизация. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Обязательная работа: Регрессия двойного удаления

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Сдайте группы тестов: вращение с уникальными метками, размещение с пустым обрамлением, удаление соседних/раздельных строк. Добавьте четыре поворота и проверку алиасинга.
4. Оставшиеся строки сохраняют порядок. Новые строки не разделяют изменяемую память. Представьте матрицу до/после.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в TetrisRules.

### `int[][] rotateClockwise(int[][] a)`

- **WHAT / contract:** Вернуть новую матрицу, повёрнутую на 90° по часовой стрелке. Прямоугольная непустая матрица. Оригинал не менять.
- **Constraints:** Непустая прямоугольная int-матрица, строки не null и ширина >0. Требуемая сложность: O(h*w) времени/памяти.
- **Examples:** rotateClockwise([[1,2,3],[4,5,6]]) → [[4,1],[5,2],[6,3]].
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `rotateClockwise`, не совпадающий с examples.
- **Typical pitfalls:** Поворот прямоугольника меняет размеры; новая внешняя матрица со старыми строками недостаточна.

### `boolean canPlace(int[][] board,int[][] piece,int x,int y)`

- **WHAT / contract:** Все ненулевые клетки piece должны лежать внутри board и попадать в нулевые клетки. y отрицательным не бывает.
- **Constraints:** board и piece непустые прямоугольные; x,y целые abs ≤ 10^6; board 0=пусто, ненулевое=занято. Требуемая сложность: O(piece.h*piece.w).
- **Examples:** board=[[0,0],[0,1]], piece=[[1]]: (0,0) → true; (1,1) → false; (-1,0) → false. Пустые клетки piece не ограничивают размещение.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `canPlace`, не совпадающий с examples.
- **Typical pitfalls:** Сначала границы, затем индексирование; учитываются только ненулевые клетки фигуры.

### `int removeFullRows(int[][] b)`

- **WHAT / contract:** На месте убрать полностью ненулевые строки; остальные опустить вниз, верх заполнить нулями. Вернуть число удалённых строк.
- **Constraints:** Непустая прямоугольная матрица ширины >0; строки — разные объекты. Требуемая сложность: O(h*w), O(1) доп. памяти.
- **Examples:** [[1,1],[0,2],[3,3]] → [[0,0],[0,0],[0,2]], результат 2.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `removeFullRows`, не совпадающий с examples.
- **Typical pitfalls:** После удаления соседней полной строки нельзя пропустить следующую; порядок неполных строк сохраняется.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 7.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :lunar-tetris -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
