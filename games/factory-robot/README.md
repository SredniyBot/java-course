# 25. Робот на заводе — Загрузка программы робота

Исполнитель команд готов. Робот начнёт движение, когда загрузчик прочитает и проверит программу, а затем корректно закроет источник.

## Один блок реализации

Замените тело **[RobotRules.readProgram](src/main/java/edu/course/games/factoryrobot/domain/RobotRules.java)**. Это единственный `TODO` игры. Остальные методы и подключение к окну готовы; дополнительных обязательных классов или расширений нет. Приватные помощники допустимы, если они делают этот блок понятнее.

## Поведение

Прочитать программу из 1–60 команд F, L, R без пробелов и переводов строк. Читать до EOF либо первого нарушения. Метод владеет переданным Reader и закрывает его ровно один раз при успехе и отказе. Вернуть исходную строку только после успешного закрытия ресурса.

Символы чувствительны к регистру. ProgramFormatException.offset() — индекс первой неверной команды; 0 для пустого ввода, 60 для превышения лимита. Требуемая сложность: O(число прочитанных символов), не более 61.

Примеры: "FFRFL" → "FFRFL"; "F X" → ProgramFormatException, offset=1; пусто → offset=0; 61 команда → offset=60.

### Отказы

- `NullPointerException`: если source равен null.
- `ProgramFormatException`: если программа пуста, содержит недопустимый символ или длиннее 60 команд.
- `ProgramLoadException`: если чтение или закрытие завершилось IOException; исходное исключение сохранено в cause.

Если нарушены несколько условий сразу, порядок их проверки не задан. Для проверки конкретного отказа нарушайте одно условие.

`IOException` переводится в `ProgramLoadException` с исходным объектом в `cause`. При read+close ошибка закрытия остаётся в `cause.getSuppressed()`. При format+close основной остаётся `ProgramFormatException`, а ошибка закрытия — в его `getSuppressed()`. Не подменяйте отказ пустой строкой; не ловите `Exception` целиком.

## На что обратить внимание

Успех, плохая команда, read failure, close failure и две ошибки одновременно должны сохранять разную диагностику.

## Как выполнить и проверить

1. Откройте метод и его вызов в `FactoryRobotGame`. Для операций, вызванных через готовый адаптер, проследите цепочку до окна.
2. До реализации выпишите результат для обычного случая и указанной границы. Затем замените демозаглушку своим кодом.
3. После лекции 3 объясните результат и состояние данных при успехе и отказе. После лекции 4 закрепите эти случаи Jupiter-тестами; тесты в `src/test/java` уже доступны.
4. Запустите проверку выбранной игры и повторите действие в окне.

```sh
./mvnw -pl :factory-robot -am verify
./mvnw -DskipTests package
java -jar app/target/java-games-app-1.0.0.jar 25
```

Все команды — из корня проекта. В PowerShell используйте `.\mvnw.cmd`. Пока блок не написан, приёмочные тесты падают, а окно запускается с неполной механикой. После изменения кода нужна пересборка.
