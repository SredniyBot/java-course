# 25. Робот на заводе

Запрограммируйте робота: с (1,1) до (5,5), обходя стены.

## Learning outcomes
Команды, состояния и независимый API. Java: Циклы, char, массивы, состояние. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 17,18,19. Уровень 3/3, ориентир 150–210 минут без установки JDK.

## Milestones
1. Напишите короткую design note: типы данных, границы ответственности, альтернативы.
2. Зафиксируйте RobotRules как адаптер для готового UI; внутренние классы, value objects и API проектируйте сами.
3. Реализуйте контракт и защитите выбор мутабельности; добавьте свои независимые тесты.
4. Обязательная защита: реализуйте запрос на изменение ниже и объясните, какие тесты защищают старое поведение.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в RobotRules.

### `int nextDirection(int direction,char command)`

- **WHAT / contract:** 0 вправо,1 вниз,2 влево,3 вверх. R поворачивает по часовой стрелке, L — против. F сохраняет направление.
- **Constraints:** direction 0..3; command F,L,R. Требуемая сложность: O(1).
- **Examples:** nextDirection(0,'L') → 3; nextDirection(3,'R') → 0; nextDirection(2,'F') → 2.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `nextDirection`, не совпадающий с examples.
- **Typical pitfalls:** Остаток отрицательного числа может быть -1; F не меняет направление.

### `Cell nextCell(int[][] map, int row, int col, int direction)`

- **WHAT / contract:** Вернуть Cell(row, col) следующей клетки, если она внутри map и равна 0; иначе Cell с прежними координатами. map не менять.
- **Constraints:** map непустая прямоугольная; row,col внутри; direction 0..3; 0=проход, любое другое значение=преграда. Требуемая сложность: O(1).
- **Examples:** nextCell([[0,0]],0,0,0) → Cell(0,1); nextCell([[0,1]],0,0,0) → Cell(0,0).
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `nextCell`, не совпадающий с examples.
- **Typical pitfalls:** row и col не x/y; при запрете хода возвращаются прежние координаты; map неизменна.

### `boolean isValidProgram(String program)`

- **WHAT / contract:** Непустая строка содержит только F,L,R. Регистр уже нормализован интерфейсом.
- **Constraints:** program не null; регистр уже может быть нормализован UI, но метод сам ничего не нормализует. Требуемая сложность: O(n).
- **Examples:** isValidProgram("FFRFL") → true; isValidProgram("") → false; isValidProgram("flr") → false; isValidProgram("F F") → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isValidProgram`, не совпадающий с examples.
- **Typical pitfalls:** Пустая программа невалидна; Character.isLetter пропускает лишние команды.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :factory-robot -am test`. Windows: `.\mvnw.cmd -pl :factory-robot -am test`.
Проверки находятся в `src/test/java/edu/course/games/factoryrobot/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 25`.
В IDE запустите `edu.course.app.Launcher` с аргументом `25`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.

## Обязательный design milestone и защита
Спроектировать RobotEngine: parse → update → snapshot, с повтором N команд.
Сохраните существующие контракты через адаптер либо документируйте согласованное изменение и обновите UI с тестами. Полная эталонная версия закрывает базовые контракты; этот запрос студент выполняет самостоятельно.

## AI policy / check questions
Можно использовать AI для объяснения API, поиска гипотез и критики тестов. В `AI_USAGE.md` укажите инструмент, задачу, что принято и как независимо проверено (или «не использовался»). Не засчитывается тест, чей expected просто скопирован из реализации.

1. Объясните `nextDirection` на входе, которого нет в примерах.
2. Какой объект изменяется, кто ещё может держать ссылку на него?
3. Какой тест упадёт при ошибке: Остаток отрицательного числа может быть -1; F не меняет направление.
4. Выполните небольшой change request без повторной генерации всего класса.
