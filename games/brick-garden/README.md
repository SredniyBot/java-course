# 05. Кирпичный сад — Щели в кирпичной стене

Мяч проходит через шестипиксельную щель. Деление координаты на шаг ошибочно уничтожает соседний кирпич.

## Что вы исследуете

Индекс сетки и попадание в поверхность различаются; отрицательное число нельзя округлять к нулю.

Темы: Индексация, деление, независимый оракул. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Перед началом

Предыдущая работа: [04. Пинг-понг с порталом](../portal-pong/README.md). Переносите её практику проверки, а не её код.

Работа 5/25. Ориентир 105–135 минут. Алгоритм и тестовый оракул выберите самостоятельно; объясните, почему они не повторяют друг друга.

## Обязательная работа: Карта попаданий

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Постройте таблицу границ кирпича и щели. Напишите тестовый оракул перебором восьми видимых интервалов и сравните columnAt на целых координатах 70..890.
4. Оракул не повторяет деление из реализации. countRemaining проверяется на прямоугольном поле с отрицательными, нулевыми и положительными клетками.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в BrickRules.

### `int columnAt(double x)`

- **WHAT / contract:** Кирпичи начинаются с x=80, шаг 100, ширина 94, всего 8. Вернуть индекс или -1, включая промежутки.
- **Constraints:** x конечен, abs ≤ 10^6. Кирпич c занимает [80+100*c,174+100*c), c=0..7. Требуемая сложность: O(1).
- **Examples:** columnAt(80) → 0; columnAt(173.9) → 0; columnAt(174) → -1; columnAt(180) → 1; columnAt(874) → -1.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `columnAt`, не совпадающий с examples.
- **Typical pitfalls:** Промежуток — не кирпич; приведение отрицательного double к int не заменяет floor.

### `int countRemaining(int[][] board)`

- **WHAT / contract:** Посчитать элементы >0; массив прямоугольный, не null.
- **Constraints:** Ненулевой объект массива, строки не null; прямоугольный, в том числе 0 строк или 0 столбцов. Требуемая сложность: O(h*w).
- **Examples:** countRemaining([[1,0],[-1,2]]) → 2; countRemaining([]) → 0.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `countRemaining`, не совпадающий с examples.
- **Typical pitfalls:** Ненулевое отрицательное значение не считается кирпичом; вход не изменять.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 5.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :brick-garden -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
