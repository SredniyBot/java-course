# 15. Ночной город — Переключатели и обратимый ход

Два одинаковых нажатия возвращают город к исходному состоянию; угол переключает меньше фонарей.

## Что вы исследуете

Закон обратимости проходит и у пустой реализации; нужны конкретные наблюдения.

Темы: Инволюция, атомарная валидация. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Перед началом

Предыдущая работа: [14. Цветной прилив](../color-flood/README.md). Переносите её практику проверки, а не её код.

Работа 15/25. Ориентир 255–285 минут. Кроме базовых методов обязательна новая модель с тестами и подключением к UI. Не складывайте состояние в static.

## Обязательная работа: Пакет нажатий

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Добавьте LightsBoard.applyMoves(List<Cell>). Сначала проверьте все координаты: любая ошибка даёт IllegalArgumentException и оставляет всё поле прежним. Затем примените пакет. Снимки независимы; UI отправляет единичный пакет.
4. Проверьте двойное нажатие, коммутативность, конкретный угол и ошибку во втором ходе пакета. Объясните атомарность.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в LightRules.

### `void toggleCross(boolean[][] a,int row,int col)`

- **WHAT / contract:** Инвертировать выбранную клетку и соседей по стороне внутри матрицы. Не трогать диагонали.
- **Constraints:** Непустая прямоугольная матрица; row,col внутри; строки разные. Требуемая сложность: O(1).
- **Examples:** toggleCross на пустом по значениям поле 2×2 в (0,0) → [[true,true],[true,false]]. Повторный вызов возвращает исходное поле.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `toggleCross`, не совпадающий с examples.
- **Typical pitfalls:** Диагональ не переключать; центральную клетку переключить ровно один раз.

### `boolean allLightsOff(boolean[][] a)`

- **WHAT / contract:** True, если нет ни одного true.
- **Constraints:** a и строки не null; пустая матрица допустима. Требуемая сложность: O(h*w).
- **Examples:** allLightsOff([[false,false]]) → true; allLightsOff([[false,true]]) → false; allLightsOff([]) → true.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `allLightsOff`, не совпадающий с examples.
- **Typical pitfalls:** Проверка не меняет лампы; один true достаточен для false.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 15.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :lights-out -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
