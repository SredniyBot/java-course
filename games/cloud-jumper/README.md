# 03. Облачный прыгун — Платформа между кадрами

За кадр персонаж перескакивает тонкую платформу. Проверка только конечной позиции теряет посадку.

## Что вы исследуете

Проверяйте пересечение отрезком движения и направление, а не близость нового положения к платформе.

Темы: Состояние до/после, интервалы. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Перед началом

Предыдущая работа: [02. Лунная доставка](../moon-lander/README.md). Переносите её практику проверки, а не её код.

Работа 3/25. Ориентир 75–105 минут. Сигнатуры и примеры заданы. Самостоятельно выберите контрпримеры.

## Обязательная работа: Пропущенный кадр

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Создайте тест одного пересечения большим шагом и двух шагов с тем же путём. Отдельно проверьте движение вверх, начало уже ниже платформы и перенос x через правую границу.
4. Сохраните oldBottom в сценарии. Покажите ошибку newBottom==platformY; перенос через произвольное число экранов вне базового контракта.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в PlatformRules.

### `boolean crossesPlatform(double oldBottom,double newBottom,double vy,double x,int platformX,double platformY)`

- **WHAT / contract:** Посадка при движении вниз (vy>0), пересечении высоты платформы снизу экрана: oldBottom<=platformY<=newBottom; центр x в [platformX,platformX+140].
- **Constraints:** Конечные координаты/скорости abs ≤ 10^6; oldBottom и newBottom — низ персонажа, y растёт вниз. Требуемая сложность: O(1).
- **Examples:** crossesPlatform(90,110,20,150,100,100) → true; при vy=0 или -20 → false; x=240 допустим, x=241 нет.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `crossesPlatform`, не совпадающий с examples.
- **Typical pitfalls:** Недостаточно проверить новую высоту: персонаж мог быть ниже платформы до шага.

### `double wrapHorizontal(double x,double width)`

- **WHAT / contract:** Если x<0, прибавить width; если x>=width, вычесть width. За шаг выход не больше width.
- **Constraints:** width ∈ (0,10^6]; x ∈ [-width,2*width). Разрешён выход не более одной ширины. Требуемая сложность: O(1).
- **Examples:** wrapHorizontal(-1,960) → 959; wrapHorizontal(960,960) → 0; wrapHorizontal(0,960) → 0; wrapHorizontal(-960,960) → 0.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `wrapHorizontal`, не совпадающий с examples.
- **Typical pitfalls:** Правая граница исключена; % для отрицательных double не даёт требуемый перенос.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 3.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :cloud-jumper -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
