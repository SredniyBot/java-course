# 03. Облачный прыгун — Посадка между кадрами

Персонаж проходит сквозь платформы. Восстановите обнаружение пересечения за целый кадр.

## Один блок реализации

Замените тело **[PlatformRules.crossesPlatform](src/main/java/edu/course/games/cloudjumper/domain/PlatformRules.java)**. Это единственный `TODO` игры. Остальные методы и подключение к окну готовы; дополнительных обязательных классов или расширений нет. Приватные помощники допустимы, если они делают этот блок понятнее.

## Поведение

Посадка при движении вниз (vy>0), пересечении высоты платформы снизу экрана: oldBottom<=platformY<=newBottom; центр x в [platformX,platformX+140].

Конечные координаты/скорости abs ≤ 10^6; oldBottom и newBottom — низ персонажа, y растёт вниз. Требуемая сложность: O(1).

Примеры: crossesPlatform(90,110,20,150,100,100) → true; при vy=0 или -20 → false; x=240 допустим, x=241 нет.

## На что обратить внимание

Проверьте большой шаг через платформу, движение вверх и начало уже ниже платформы.

## Как выполнить и проверить

1. Откройте метод и его вызов в `CloudJumperGame`. Для операций, вызванных через готовый адаптер, проследите цепочку до окна.
2. До реализации выпишите результат для обычного случая и указанной границы. Затем замените демозаглушку своим кодом.
3. После лекции 3 объясните результат и состояние данных при успехе и отказе. После лекции 4 закрепите эти случаи Jupiter-тестами; тесты в `src/test/java` уже доступны.
4. Запустите проверку выбранной игры и повторите действие в окне.

```sh
./mvnw -pl :cloud-jumper -am verify
./mvnw -DskipTests package
java -jar app/target/java-games-app-1.0.0.jar 3
```

Все команды — из корня проекта. В PowerShell используйте `.\mvnw.cmd`. Пока блок не написан, приёмочные тесты падают, а окно запускается с неполной механикой. После изменения кода нужна пересборка.

## Готово, когда

- Описанное действие работает в окне, а тесты выбранного модуля проходят без изменения ожидаемых результатов и без включения preview в тестах.
- Проверены обычный случай и перечисленные границы; для отказа проверены тип исключения и сохранность данных, если это обещано контрактом.
- Вы можете ответить: **Почему сравнения новой высоты с высотой платформы недостаточно?**

Сдайте реализацию и свои проверки в одном коммите. Краткое объяснение спорного решения достаточно оставить в описании коммита — отдельные DESIGN/REGRESSION/AI_USAGE-файлы не нужны. Если пользовались AI, укажите, что проверили самостоятельно; на защите потребуется объяснить код и изменить один сценарий.
