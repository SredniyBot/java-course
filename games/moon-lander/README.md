# 02. Лунная доставка

Посадите корабль на зелёную площадку со скоростью не выше 55.

## Learning outcomes
Шаг симуляции и составной контракт. Java: double, условия, логические операции. После работы студент умеет объяснить контракт и подтвердить его тестом, а не только показать работающий экран.

## Prerequisites
Базовый синтаксис Java, методы и запуск Maven. Предыдущие игры/знания: 01. Уровень 1/3, ориентир 45–60 минут без установки JDK.

## Milestones
1. Нарисуйте два граничных примера на бумаге.
2. Реализуйте первый метод по описанию; прогоните тесты.
3. Реализуйте остальные методы, добавьте тест на границу.
4. Проверьте обычный ход и перезапуск окна.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в LanderPhysics.

### `double nextVerticalSpeed(double current, boolean engine, double dt)`

- **WHAT / contract:** Ускорение вниз 65, двигатель добавляет ускорение вверх 130. Вернуть новую скорость.
- **Constraints:** current конечна, abs ≤ 10^6; dt ∈ [0,1], секунды; положительная скорость направлена вниз. Требуемая сложность: O(1).
- **Examples:** nextVerticalSpeed(10,false,0.2) → 23; nextVerticalSpeed(10,true,0.2) → -3; dt=0 сохраняет current.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `nextVerticalSpeed`, не совпадающий с examples.
- **Typical pitfalls:** Двигатель меняет ускорение, а не устанавливает фиксированную скорость.

### `boolean isSafeLanding(double x,double nextVerticalSpeed)`

- **WHAT / contract:** Успех: центр x в [385,555] и модуль скорости <=55.
- **Constraints:** x и nextVerticalSpeed конечны, abs ≤ 10^6. Требуемая сложность: O(1).
- **Examples:** isSafeLanding(385,55) → true; isSafeLanding(555,-55) → true; isSafeLanding(384,0) → false; isSafeLanding(470,56) → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isSafeLanding`, не совпадающий с examples.
- **Typical pitfalls:** Проверяются обе границы площадки и модуль скорости, соединение условий — AND.

## Tests и запуск
Из корня репозитория: `./mvnw -pl :moon-lander -am test`. Windows: `.\mvnw.cmd -pl :moon-lander -am test`.
Проверки находятся в `src/test/java/edu/course/games/moonlander/domain`. Это Jupiter, не отдельный main.
После полной сборки `./mvnw verify` запустите `java -jar app/target/java-games-app-1.0.0.jar 2`.
В IDE запустите `edu.course.app.Launcher` с аргументом `2`. F5 сбрасывает игру, F6 ставит на паузу; код после правки нужно перекомпилировать.
В студенческой выдаче тесты изначально красные из-за незаполненных методов. Это ожидаемо; отключать их нельзя.
