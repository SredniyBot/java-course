# 02. Лунная доставка — Посадка по приборам

Индикатор площадки зелёный, но корабль разбивается при движении вверх: знак скорости потерялся в условии.

## Что вы исследуете

Положение и скорость имеют независимые границы; правильное положение не компенсирует слишком большую скорость.

Темы: double, единицы, AND, накопление состояния. Для доказательства корректности используйте понятия лекции 3: контракт, класс входов, независимый oracle, граница и регрессия. Формальные доказательства не требуются; требуется объяснить основание каждого важного assertion.

## Перед началом

Предыдущая работа: [01. Звёздный курьер](../star-courier/README.md). Переносите её практику проверки, а не её код.

Работа 2/25. Ориентир 60–90 минут. Сигнатуры и примеры заданы. Самостоятельно выберите контрпримеры.

## Обязательная работа: Протокол посадки

1. Запустите демо и опишите наблюдаемый дефект: действие → результат → ожидаемое поведение. Баннер показывает вызванные незавершённые методы, а не процент готовности.
2. Реализуйте базовые методы по контрактам ниже. Заглушку ExercisePreview.unfinished заменяйте целиком; не включайте preview внутри acceptance-тестов.
3. Составьте таблицу комбинаций: левее/на краю/внутри/правее и скорость -56/-55/0/55/56. Выберите набор, различающий ошибки в каждом условии. Проверьте dt=0 и два последовательных шага без смены тяги.
4. Приведите контрпример к speed<=55 без модуля. Для double обоснуйте допуск; сравнение landing остаётся точным по контракту.
5. Повторите исходный сценарий в окне. Отдельно проверьте F5, F6 и ошибочный ввод. Сохраните команду проверки и её результат.

## Приёмка

Базовые публичные тесты обязательны, но не исчерпывают работу. Новая часть оценивается по условиям пункта 3 и доказательствам пункта 4. Зелёные tests без обязательной новой функциональности не означают завершение. Нельзя ослаблять существующий контракт, подгонять expected или удалять проверки ради зелёного статуса.

## Контракты заданий
WHAT — требуемый результат; contract — поведение и изменения; constraints — допустимые входы. Предусловия задаёт вызывающий код: вне явно описанного домена поведение не специфицировано, скрытые тесты не требуют придуманной валидации. Null запрещён, кроме явно разрешённых элементов history. Входы не изменять, если контракт прямо не требует мутацию. Нельзя использовать время, случайность, I/O или глобальное изменяемое состояние в LanderPhysics.

### `double nextVerticalSpeed(double current, boolean engine, double dt)`

- **WHAT / contract:** Ускорение вниз 65, двигатель добавляет ускорение вверх 130. Вернуть новую скорость.
- **Constraints:** current конечна, abs ≤ 10^6; dt ∈ [0,1], секунды; положительная скорость направлена вниз. Требуемая сложность: O(1).
- **Examples:** nextVerticalSpeed(10,false,0.2) → 23; nextVerticalSpeed(10,true,0.2) → -3; dt=0 сохраняет current.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `nextVerticalSpeed`, не совпадающий с examples.
- **Typical pitfalls:** Двигатель меняет ускорение, а не устанавливает фиксированную скорость.

### `boolean isSafeLanding(double x,double nextVerticalSpeed)`

- **WHAT / contract:** Успех: центр x в [385,555] и модуль скорости <=55.
- **Constraints:** x и nextVerticalSpeed конечны, abs ≤ 10^6. Требуемая сложность: O(1).
- **Examples:** isSafeLanding(385,55) → true; isSafeLanding(555,-55) → true; isSafeLanding(384,0) → false; isSafeLanding(470,56) → false.
- **Acceptance criteria:** все приведённые примеры воспроизводятся; границы включены/исключены точно по контракту; результат и допустимые изменения входов проверены отдельными assertions. Добавьте минимум один собственный случай для `isSafeLanding`, не совпадающий с examples.
- **Typical pitfalls:** Проверяются обе границы площадки и модуль скорости, соединение условий — AND.

## Запуск и проверки

Из корня: ./mvnw -DskipTests package, затем java -jar app/target/java-games-app-1.0.0.jar 2.
На Windows используйте .\mvnw.cmd. Это компиляция и запуск демо, не приёмка.

Приёмка: ./mvnw -pl :moon-lander -am verify. Незавершённые методы дают IncompleteExerciseException.
При запуске окна та же заглушка даёт намеренно неполноценное поведение. Частично реализованная игра использует ваши готовые методы; ошибки вашего кода не заменяются демо.
F5 сбрасывает сцену; после изменения кода нужна пересборка. В каталоге src/test/java — настоящие Jupiter-тесты.
