# 14. Цветной прилив — Заливка области

Выбор цвета пока не меняет поле. Перекрасьте только связанную по сторонам область от левого верхнего угла.

## Один блок реализации

Замените тело **[FloodRules.fillFromOrigin](src/main/java/edu/course/games/colorflood/domain/FloodRules.java)**. Это единственный `TODO` игры. Остальные методы и подключение к окну готовы; дополнительных обязательных классов или расширений нет. Приватные помощники допустимы, если они делают этот блок понятнее.

## Поведение

Перекрасить компоненту клетки [0][0] по четырём сторонам. Использовать очередь из двух int[] размером h w. Помечать клетку новым цветом ДО добавления. Если цвет не меняется, сразу выйти.

Непустая прямоугольная матрица width>0; h*w ≤ 10^6; строки разные; любой int цвет. Требуемая сложность: O(h*w) времени/памяти.

Примеры: fillFromOrigin([[1,2],[2,1]],9) → [[9,2],[2,1]]; color=1 ничего не меняет.

## На что обратить внимание

Диагональное касание не соединяет области; новый цвет может совпасть с исходным.

## Как выполнить и проверить

1. Откройте метод и его вызов в `ColorFloodGame`. Для операций, вызванных через готовый адаптер, проследите цепочку до окна.
2. До реализации выпишите результат для обычного случая и указанной границы. Затем замените демозаглушку своим кодом.
3. После лекции 3 объясните результат и состояние данных при успехе и отказе. После лекции 4 закрепите эти случаи Jupiter-тестами; тесты в `src/test/java` уже доступны.
4. Запустите проверку выбранной игры и повторите действие в окне.

```sh
./mvnw -pl :color-flood -am verify
./mvnw -DskipTests package
java -jar app/target/java-games-app-1.0.0.jar 14
```

Все команды — из корня проекта. В PowerShell используйте `.\mvnw.cmd`. Пока блок не написан, приёмочные тесты падают, а окно запускается с неполной механикой. После изменения кода нужна пересборка.

- Проверены обычный случай и перечисленные границы; для отказа проверены тип исключения и сохранность данных, если это обещано контрактом.
