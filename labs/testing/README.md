# Практика к лекции 4: можно ли доверять заправщику?

Два курьерских корабля передают топливо перед вылетом. Метод выглядит убедительно, happy-path тест зелёный. Ваша задача — построить основания доверять ему, а затем исправить обнаруженные дефекты.

Это отдельная работа после игр 01–04, 120–150 минут плюс короткая защита. Не требуется решить все 25 игр. Основано на обсуждённой лекции 4: specification → oracle → boundaries → properties → coverage/mutation → regression. В лекции был перевод между Account; здесь тот же инженерный вопрос перенесён на запас топлива, а не на банковскую систему.

## Контракт версии 1

FuelTank хранит long units>=0; отрицательное начальное значение отклоняется IllegalArgumentException.
FuelTransfer.transfer(from,to,amount):

- null-резервуар: NullPointerException;
- amount<0, недостаток топлива или переполнение получателя: IllegalArgumentException;
- amount==0: допустимый no-op;
- from==to: допустимый no-op, если amount<=исходного остатка; избыточный amount всё равно отклоняется;
- успешный перевод между разными объектами уменьшает from и увеличивает to ровно на amount;
- при любом отказе оба объекта полностью сохраняют прежнее состояние.

Не обещаются многопоточность, сохранение на диск и автоматические повторы. Когда несколько предусловий нарушены одновременно, порядок выбора ошибки не специфицирован. Проверяйте одно нарушение за раз.

## Этап A — сначала свидетельства (35 минут)

Production-код пока не меняйте. Составьте TEST_PLAN.md: классы входов, representative, expected, источник expected, какую ошибку различает. Добавьте Jupiter-тесты:

1. параметризованные границы 0, весь остаток, на единицу больше, отрицательное;
2. два разных объекта и alias одного;
3. overflow получателя и неизменность обоих резервуаров при отказе;
4. null, конструктор, последовательность успешного и неуспешного переводов.

Ожидается красный прогон: кандидат намеренно неисправен. Сохраните первый минимальный контрпример и красный вывод в REGRESSION.md. Не ставьте assertThrows на AssertionError и не запускайте это через деморежим.

## Этап B — свойства и оракул (30 минут)

Свойство сохранения суммарного топлива проверяйте через BigInteger: сумма двух long сама может переполниться. Генерируйте только допустимые случаи с фиксированным seed; укажите seed и вход при падении. Дополните свойство конкретным примером: пустой transfer тоже сохраняет сумму!

Проверьте независимость постороннего резервуара и инвариант отсутствия отрицательных остатков. На отказах проверяйте полный snapshot до/после. Не вычисляйте expected повторением production-алгоритма.

## Этап C — исправление и проверка тестов (35 минут)

Исправьте FuelTransfer, сохранив API. Сначала валидируйте и вычислите будущие значения, затем меняйте состояние. Объясните, почему исключение между двумя записями не оставляет половину перевода.

Команды из корня:

    ./mvnw -pl :testing-lab -am test
    ./mvnw -pl :testing-lab -am verify
    ./mvnw -Pmutation -pl :testing-lab -am verify

Windows: mvnw.cmd. Отчёты: labs/testing/target/site/jacoco и target/pit-reports.
PIT threshold=0 для этой лаборатории намеренно: цель — объяснить каждый surviving/no-coverage mutant, а не подобрать число. Это не критерий успешной приёмки.

## Что сдавать

- TEST_PLAN.md, тесты, исправление, красный→зелёный пример;
- TEST_REVIEW.md: один mutant, убитый вашим тестом; один переживший или эквивалентный mutant с объяснением (если все убиты — вручную внесите no-op и покажите отличающий тест);
- ограничения: чего ваши тесты не доказывают, почему coverage не равен корректности;
- AI_USAGE.md: гипотеза AI, независимо проверенный пример и принятое/отклонённое предложение.

## Изменение требований на защите

Появляется резерв reserve>=0: после перевода у отправителя должно оставаться не меньше reserve. Сначала допишите контракт для alias и zero, затем тест на границу, затем измените API. Старый API должен сохранять поведение версии 1 (reserve=0).

## Самопроверка

Почему happy-path не ловит partial update? Почему round-trip не исключает два одинаковых дефекта? Что даёт BigInteger в оракуле? Какой тест отличает zero no-op от negative? Где находится минимальный контрпример?
