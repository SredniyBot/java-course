# Вклад и учебный процесс

1. Откройте README игры. Сначала сформулируйте ожидаемое поведение и владельца изменяемых данных.
2. Создайте ветку `exercise/<slug>-description` или `fix/short-description`. Не смешивайте несколько игр в одном изменении без причины.
3. Для исправления сначала воспроизведите дефект маленьким падающим Jupiter-тестом. Expected следует из контракта, не из другой копии того же алгоритма.
4. Реализуйте решение, выполните `./mvnw -pl :<slug> -am verify`; полный `./mvnw clean verify` требуется после реализации всех 25 игр. Windows использует `mvnw.cmd`.
5. Если изменяете UI, проверьте обычный ход, ошибочный ввод, достижение цели, паузу и перезапуск в окне; опишите результат. Headless smoke test не заменяет эту проверку.
6. В PR укажите проблему, изменение поведения, тесты и ограничения. При изменении контракта синхронно обновите Javadoc, README, catalog.json.

Форматирование: `./mvnw spotless:apply`. Не правьте отформатированный код вручную ради личного стиля.
Не добавляйте в этот репозиторий приватные материалы преподавателя, скрытые тесты или эталонные решения.

## Пример первого Git-сохранения

```sh
git init -b main
git add .
git commit -m "Add Java games course"
```

Автор Git настраивается пользователем. Build outputs, настройки IDE и локальные кэши не коммитятся. Не коммитьте ключи, токены и журналы внешних сервисов.
