# ADR 003: один эталон и экспортируемые заготовки

Статус: принято. Дата: 2026-09-21.

Контекст: две вручную редактируемые копии sem2/sem2Answers расходятся; непонятные TODO вынуждают угадывать замысел автора. Нужно сохранить игры и сделать нагрузку постепенно самостоятельнее.

Решение: в закрытом преподавательском комплекте единственный source of truth для исполняемого кода — games/<slug>/src/main. Для каждого из 55 методов контракт опубликован рядом с методом и в README. catalog.json перечисляет методы для безопасного экспорта. Закрытый инструмент экспорта удаляет тела отмеченных методов по структурным границам, заменяет их направляющим TODO и явным UnsupportedOperationException, вырезает teacher resources и outputs. Экспорт отказывается перезаписывать существующую папку.

01–06: пошаговое начало и формулы, фиксированный API. 07–15: самостоятельные алгоритмы и декомпозиция. 16–25: предметный класс правил остаётся границей подключения готового UI, но внутреннюю архитектуру студент определяет сам; обязательны DESIGN.md, собственные типы/API и запрос на изменение из README. Это обеспечивает самостоятельный design без переписывания графики ради каждого занятия.

Эталон закрывает базовые контракты, а не решает за студента запросы защиты. Отдельная студенческая выдача компилируется, но её тесты до реализации красные. Их нельзя скрывать через @Disabled, пустые тесты или fallback к эталону. Для практики выбирают один модуль с -pl/-am.

Альтернатива: хранить 50 модулей starter+solution или всегда давать ответы рядом. Отклонена из-за дублирования и случайной утечки. Git-ветки сами по себе не обеспечивают секретности: полная история может содержать решения. Export не включает .git.

Известное ограничение: тела последних заданий по-прежнему имеют фасадные сигнатуры для UI; самостоятельный API/design проверяется обязательным milestone и защитой, а не переименованием классов ради вида. Дублируемые контрактные тексты обновляются вместе; review проверяет соответствие примерам.
