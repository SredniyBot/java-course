# Java Course

25 учебных игр на **Java 21**. Интерфейс готов; вам нужно реализовать одно законченное действие в выбранной игре и проверить его.

## Запуск

Установите JDK 21 и проверьте `java -version`. Откройте терминал в корне проекта, рядом с `pom.xml`.

```sh
./mvnw -DskipTests package
java -jar app/target/java-games-app-1.0.0.jar
```

В **Windows PowerShell** вместо `./mvnw` пишите `.\mvnw.cmd`. При первой сборке нужен интернет. Maven отдельно устанавливать не нужно.

Откроется меню с поиском. Для прямого запуска добавьте номер игры:
`java -jar app/target/java-games-app-1.0.0.jar 1`.

Демо работает и с незаполненными TODO, но часть механик отсутствует. **F5** — заново, **F6** — пауза, **F1** — помощь. После изменения кода пересоберите проект.

В IDE откройте корневой `pom.xml` и выберите SDK 21. Если терминал использует другую Java, настройте `JAVA_HOME` на JDK 21.

## Maven за минуту

Maven компилирует код, скачивает библиотеки и запускает тесты. Настройки хранятся в **pom.xml**. **Wrapper** (`mvnw`, `mvnw.cmd`) запускает закреплённую версию Maven.

**Модуль** — отдельная часть сборки со своим pom.xml. Каждая игра — модуль; окно, меню и тестовые данные вынесены отдельно. Это модули Maven, не Java-модули с `module-info.java`.

| Команда / параметр | Для чего |
|---|---|
| `test` | Компиляция и тесты |
| `package` | Дополнительно собрать JAR |
| `verify` | Тесты, форматирование и проверка покрытия |
| `clean` | Удалить предыдущую сборку |
| `-pl :star-courier -am` | Выбрать игру и собрать её зависимости |
| `-DskipTests` | Собрать демо без выполнения тестов |
| `spotless:apply` | Отформатировать код |

Например, проверить первую игру:

```sh
./mvnw -pl :star-courier -am verify
```

Имя другого модуля смотрите в его `pom.xml`, поле `artifactId`. Все команды запускайте из корня.

## Ваша работа

1. Выберите игру и прочитайте **games/<имя>/README.md**: там условия, контракты и критерии приёмки.
2. Найдите единственный TODO игры в `src/main/java/.../domain`. Замените тело этого метода своим кодом; остальные части уже готовы.
3. Запустите тесты из `src/test/java`, добавьте граничные случаи. Дополнительного обязательного блока реализации нет.
4. Выполните `verify` выбранного модуля, проверьте игру в окне и сдайте материалы, перечисленные в задании.

**Пока TODO не решены, их тесты должны падать.** Не отключайте проверки и не включайте деморежим внутри тестов. Успешная сборка демо не означает выполнение задания.

Остальная структура: `app` — меню; `platform/desktop` — окно и рисование; `learning/scaffolding` — демозаглушки; `testing/fixtures` — тестовые данные. Обычно эти части менять не нужно. Папки `target` создаются автоматически.

После лекции о тестировании: **[«Можно ли доверять заправщику?»](labs/testing/README.md)**. Решать все игры перед этой практикой не требуется.

## Связь с лекциями

Лекция 3 теперь посвящена особенностям Java перед тестированием; тест-дизайн — лекция 4. До неё разбирайте результат вызова и состояние данных, затем оформляйте те же сценарии тестами.

Задания на исключения встроены в единственный блок соответствующей игры:

- [06. Змейка](games/courier-snake/README.md): валидация до изменения двух массивов.
- [12. Буквенный лабиринт](games/word-maze/README.md): ошибка аргумента и ошибка индекса.
- [19. Холст времени](games/time-canvas/README.md): отказ копирования не разрушает историю.
- [21. Unicode](games/unicode-safari/README.md): явное исключение вместо случайной ошибки внутри String.
- [22. Радио](games/utf8-radio/README.md): checked-исключение декодера и готовый обработчик в UI.
- [24. Полёт](games/ballistic-mail/README.md): границы числового API и неизменяемое состояние.
- [25. Робот](games/factory-robot/README.md): try-with-resources, throws, cause и suppressed.
