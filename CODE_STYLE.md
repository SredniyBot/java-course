# Стиль и границы сложности

Автоматический стиль — Google Java Format 1.28.0 через Spotless. Два пробела, обычные имена Java, UTF-8. `spotless:check` входит в verify. В production не оставляйте неиспользуемые импорты, тестовый main и закомментированные реализации.

Используйте конкретные имена и небольшие методы. Чистые статические функции допустимы; глобальное изменяемое static state — нет. Массив, лежащий в static final, всё ещё изменяем. Общая палитра поэтому хранится приватным immutable List.

Предметные классы правил не зависят от Swing, времени, файлов, случайности и скрытой локали. Предусловия явно опубликованы. Не добавляйте произвольную валидацию каждого внутреннего вызова: там, где вход вне домена, контракт этого не обещает. На внешних границах (ввод команды, UTF-8, аргументы launcher) ошибка должна обрабатываться явно.

Предпочитайте композицию. GamePanel владеет DesktopGame и GameSession; игры не наследуют JPanel. Единственное наследование Swing — необходимый адаптер GamePanel → JPanel. Не создавайте интерфейс для каждой арифметической функции и общий базовый класс для правил всех игр.

Records удобны для значений: Velocity, Cell, GameDescriptor. Record с массивом не обеспечивает глубокую неизменяемость: либо копируйте данные на входе и выходе, либо явно определяйте владение. Мутабельные массивы сохранены там, где изменение на месте является темой задания.

Тесты: имя описывает поведение, Arrange/Act/Assert читаются без комментария к каждой строке. Для чисел с плавающей точкой используйте обоснованный допуск; для массивов сравнивайте содержимое и отдельно проверяйте независимость ссылок. Parameterized tests нужны для таблиц одинакового поведения, а не для скрытия разнородных сценариев. Никаких sleep, сетевых зависимостей и случайных seed в CI.

Минимальный статический контроль: javac `-Xlint:all,-serial -Werror`, Maven Enforcer (версии и согласованность зависимостей), Spotless. Исключение serial касается Swing-компонента, который приложение не сериализует. Добавляйте PMD/SpotBugs только под конкретный класс дефектов и после оценки шума; дублирующие анализаторы не нужны.

Именование и расположение: [STRUCTURE](docs/STRUCTURE.md). Зависимости дополнительно проверяет ArchUnit. Wildcard imports не используются. Renderer не читает контроллер или GameSession, данные получает аргументами.
